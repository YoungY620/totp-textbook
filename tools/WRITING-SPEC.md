# 章节撰写规范（子代理必读）

本项目是一本**双语在线教材**（mdBook）：TOTP / 验证器 / 密码管理器的起源与演进。
每一章对应**一篇一手论文或标准**，再加上「相关文献」的扩展阅读。

> **为什么有这份规范。** 论文集合不像一门课，**事先没有统一的叙述框架**。全书先由主代理交叉讨论、
> 定下覆盖「历史源头 → 繁荣发展 → 当前现状」的框架（`tools/narrative-framework.md`），再逐章编排。
> 你的每一章都要**落在框架里**，**每个事实都能追到真实材料**，而且要**讲成一个故事的一部分**。

## 你的产出（严格按此路径写文件）

你负责的每一章要写**两个文件，文件名完全相同**：

- 英文：`/Users/moonshot/dev/working/totp-textbook/book-en/src/chapters/<slug>.md`
- 中文：`/Users/moonshot/dev/working/totp-textbook/book-zh/src/chapters/<slug>.md`

**只写这两个文件。** 不要改 `SUMMARY.md`、`book.toml`、js/css、其他章节。不要留临时文件。

## 内容来源（铁律：反幻觉）

- 正文只能来自该章一手文献（及其引用的公开材料）。先真的把原文读下来（WebSearch/FetchURL 取开放获取 PDF）。
- 数字、算法参数、定理、攻击数量、实验结论必须与原文一致。**不确定就不要写**，或写「原文未明确」。
- 开放获取优先：RFC 站、USENIX 官方 PDF、arXiv/ePrint、作者主页、W3C 规范。付费墙先找预印本；
  找不到就显式标注"基于摘要/二手描述"。**绝不用盗版站**。
- 与 handoff 冲突时**以原文为准**，并在正文自然按原文写。
- **交付时必须附「事实核对清单」**（见回报格式）。

## 故事性（硬要求，别敷衍）

这本教材要**有故事性**。每章都必须做到：

1. **开篇钩子**：正文第一段用一个**具体的、有画面感**的问题或事故开场，不要用抽象陈述。
   用 `<div class="hook"> … </div>` 包住（2–4 句）。
2. **题外话边栏**：每章**恰好一条**，用下面的 HTML 结构。内容**必须**出自
   `tools/anecdotes.md`（已核实来源的轶事清单）里属于本章的条目，或该章原文中可查证的具体细节。
   **不许编造**；分不清是"论文结论"还是"业界背景"就明确标注。
3. **回响（呼应伏笔）**：在本章第 6 节或第 7 节，**明确写出**本章呼应了前面哪一章的哪个母题
   （如"共享秘密被放回服务器""时间即信任""加密了但钥匙就在旁边"），以及给后面埋了什么钩子。
   框架里的母题见 `tools/narrative-framework.md` 第二节。

边栏结构（照抄，只换文字）：

```html
<div class="aside">
<p><span class="aside-label">题外话 · <小标题></span></p>
<p><正文，3–6 句></p>
<p class="aside-source">出处：<来源，如 RFC 1760 §X / 作者会议 slides / 业界事件（非论文内容）></p>
</div>
```

英文版把 `题外话` 换成 `Aside`、`出处：` 换成 `Source:`。

## 章节结构（中英文一致）

```markdown
# <章标题>

<div class="source-card">
<p><strong>本章文献：</strong> 作者. <em>标题</em>. 出处, 年份. <a href="PDF链接">原文 PDF</a></p>
<p><strong>一句话：</strong> 这篇文献解决了什么问题、结论是什么。</p>
</div>

<div class="hook">……开篇钩子……</div>

## 1. 背景与动机          ← 威胁/难题；作者的问题意识
## 2. 核心内容            ← 定义、算法、协议、构造、公式
## 3. 安全分析 / 攻击 / 实验评估
## 4. 适用场景与迁移边界  ← 结果意味着什么、能迁移到哪、前提与局限
## 5. 相关文献与领域现状  ← 3~6 条真实文献 + 作者对方向的判断
## 6. 小结与回响          ← 5~8 条要点 + 明说本章的伏笔呼应
## 参考文献
```

（`题外话` 边栏放在第 3 或第 4 节之后、第 6 节之前的位置最自然。）

### 两处必须写足

**「动机」与「评估效果 / 适用场景」决定一篇工作能迁移到什么场景**：

- 第 1 节：作者要解决什么真实问题？威胁模型/使用场景？此前方法为何不够？
- 第 3 节：评估本身——设置、指标/数据集、结论强度（形式化证明/实验/测量）、反例。**数字与原文一致。**
- 第 4 节：能迁移到哪些场景、前提假设、何时不成立、对今天实践的含义。把"动机→方法→评估→边界"串成线。

### 「相关文献」是理解作者"对整个方向的理解"的窗口

不只罗列：写出作者认为领域现状是什么、谁和谁对立、共识在哪、作者把自己定位在哪
（改良派/革命派/系统化者）。3~6 条，各给链接。

## 公式与排版

- 行内 `$...$`，独立公式 `$$...$$`（成对、独占一行）。构建期的 `mathprotect` 预处理器会自动处理两类坑：
  加倍反斜杠（`\\`、`\{`、`\,`、`\begin{aligned}` 照常写），并把数学里的 `_` 与 `*` 转义，避免被
  Markdown 当成强调起始符。**所以你按正常 LaTeX 写即可**，不需要为绕开 Markdown 而改写公式
  （不必写成 `\mathsf{ID_C}` 之类）。
- **写完自查每个 `$` / `$$` 都成对闭合**（未闭合会让整页渲染失败）。
- 代码与口令示例用反引号或代码块。不要用 emoji。表格正常用。

## 篇幅与文风

- 英文约 1200–2200 词（**含边栏**）；中文约 2500–4500 字。信息密度优先。
- 教材散文，不是论文摘要的罗列。定义清楚、逻辑连贯、必要推导给出。

## 双语要求

中英两版**结构与知识点一一对应**，但各按该语言习惯写，不逐字直译。术语首现中英并列。两边都要正确。

## 回报格式（必须）

1. 写了哪些文件、各自字数；
2. **事实核对清单**：关键数字/结论 → 原文出处（章节/附录/表），以及边栏的出处；
3. **存疑/未获取清单**；
4. 与 handoff 或既有描述不一致之处（若有）。
